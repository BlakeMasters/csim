# Contrastive distillation and calibrated decisions for virtual-cell work

Research checked: **2026-09-25**. The requested RLCD is **Reinforcement Learning from Contrastive Distillation**. TypeSafe's **Reinforcement Learning for Calibrated Decisions** is a separate possible extension. Neither has been implemented, trained, or evaluated in this project. This review used public documents only; no hosted-model requests, training, dependency installation, or biological data acquisition occurred.

**Recommendation:** evaluate contrastive distillation for an experiment-design or model-review assistant after establishing independently scored examples. Keep physical or assay prediction training tied to measured or explicitly synthetic targets. A calibrated probability head is a useful separate hypothesis; first compare a supervised predictor plus simple calibration with the added cost of RL. Both ideas are plausible here, but the inspected studies do not establish that either improves virtual-cell prediction.

## What contrastive RLCD actually contributes

The key original labeling assumption is `response_from_positive_prompt > response_from_negative_prompt`, without checking which response is actually correct. The positive and negative prompts should differ chiefly along the desired attribute so that unrelated wording does not become the preference signal. This is a data-generation technique inside an alignment pipeline, not an environment that supplies verified physical transitions. [Original method, sections 3.1-3.2](https://proceedings.iclr.cc/paper_files/paper/2024/file/5bd09a559a8c8e230697107b0f353d39-Paper-Conference.pdf)

For this project, asking for a scientifically accurate answer and an inaccurate answer would not establish which output correctly predicts a measured cell. Likewise, ranking an elegant explanation above an awkward one can improve communication while leaving numerical error unchanged. These are transfer risks inferred from the labeling mechanism, not outcomes measured in the RLCD paper.

There is still a useful direction: create paired experiment proposals or model critiques, then test whether contrasting prompts produce distinctions that independent reviewers or objective checks confirm. If preferences are assigned using verified numerical errors or measured outcomes, describe the result as a **task-specific, externally scored preference adaptation**. It changes the original automatic labeling assumption and should receive its own ablations.

A high probability cannot override those requirements.

## Calibration is a separate measurable objective

For a binary event with true conditional probability `q`, minimizing expected Brier loss gives
`E[(p-y)^2] = (p-q)^2 + q(1-q)`, whose minimum occurs at `p=q`. This elementary identity illustrates the proper-score principle; supervised optimization can use it directly. RL is not required merely to output probabilities. Its potential value needs a reason such as a discrete decision sequence, sampling-dependent rewards, or interaction with future observations. [Proper-scoring methodology](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)

That population optimum assumes the specified outcome distribution and appropriate labels. A model can fit wrong labels, miss the optimum, or encounter a changed distribution. Calibration alone also does not imply useful discrimination: always predicting a stable base rate can be calibrated while identifying no informative cases. Measure predictive skill and decision utility alongside calibration. These are design implications, not a promise from a particular training algorithm.

The new Jev evaluation makes the cohort issue concrete: for its generic Noul question, section 4.4 reports pooled expected calibration error (ECE) 0.047 but median per-benchmark ECE 0.168, compared with a finite-sample perfectly calibrated null of 0.074; 24 of 31 benchmarks exceed that null's 95th percentile. Appendix E distinguishes canonical benchmarks from benchmark/model files. These results support local evaluation of probabilities, not a universal transfer guarantee. [Just Ask Jev](https://arxiv.org/html/2609.29429v1)

## Smallest informative evaluation protocol

1. **Declare one task.** Choose either proposal quality, numerical-error events, a measured biological event, or a response distribution. Specify its observation operator, horizon, feature order, units, missing-data policy, metric, and acceptance criterion before fitting. Do not merge these outcomes into one general reliability score.
2. **Freeze the dataset and grouping.** Keep experimental units, trajectories, culture batches/donors where applicable, and designated perturbations disjoint. Biological calibration requires experimental observations. Calibration against synthetic targets establishes only behavior relative to those synthetic targets.
3. **Allocate calibration explicitly.** With the current `train/validation/test` schema, select model structure using grouped inner folds within training, then reserve validation for calibration and threshold fitting. Keep the final test untouched. A dedicated fourth calibration role would need a deliberate schema extension; the current validator does not provide it.
4. **Compare equal-information candidates.** Start with a cheap supervised predictor or preference classifier and its calibrated variant. For contrastive generation compare positive-only supervised distillation, original automatic preferences, and independently checked preferences. A later RL arm must receive the same observations and allowable outputs.
5. **Freeze all fitted pieces.** Bind model, preprocessing, calibrator, event/rubric definition, threshold, baselines, and dataset/splits before the final holdout. Current verification opens dataset artifacts, one model file and one preprocessing file. Include any selector/calibrator in a verified bundle or extend the verified artifact registry; arbitrary metadata paths/hashes are not recursively verified. The campaign does not execute evaluators or restrict holdout access.
6. **Report more than pooled calibration.** Use appropriate proper scores, discrimination, reliability plots with sample counts, coverage/error under abstention, and decision utility. Report each held-out cohort, uncertainty using experimental-unit grouping, failed cases, and exclusions. Do not treat a threshold selected on the final holdout as a deployable result.
7. **Charge the full work.** Include candidate generation, teacher/comparator computation, labeling, reward training, PPO or other optimization, failed trials, calibration, inference, evaluation, and persistence. Compare gain per total cost. Stop an RL branch that adds no material held-out value over the calibrated supervised baseline.

An active-learning or self-play loop must keep its acquisition pool separate from the final evaluation cohort. Freeze the evaluation candidate; subsequent learning starts a new development campaign. Exploration can discover difficult examples inside a simulator, but experimental observations are still needed to establish biological transfer.
